# Schema design

> The decision record for `@sekhmet/schema`, kept as project history. The user
> docs are the package's [README](../../packages/schema/README.md) and its
> [`docs/`](../../packages/schema/docs/) pages, and the API reference is on
> [JSR](https://jsr.io/@sekhmet/schema/doc).

Status: **Accepted** (2026-11-16). Implementation is in progress; each section
names the feature directory that owns it.

`@sekhmet/schema` validates and transforms values. A `Schema<I, O, E>` holds a
runner (with, since #32, its node and annotations; see
[Schemas describe themselves](#schemas-describe-themselves-32)): `parse`
runs it under a panic runtime to a `Vow<Outcome<O, E, unknown>>`, which is
resolved inside the call when the parse finished synchronously (since #84;
see [Parsing to a Vow of an Outcome](#parsing-to-a-vow-of-an-outcome-84);
before it, a `Potential` (`Sync` | `Async`) recorded this). That makes a
Sekhmet schema more expressive than a
[Standard Schema](https://standardschema.dev): its input is typed, its error
is typed, a bug in user code is a `Panicked` outcome rather than a failure,
and callers can know whether a parse is async (`parseSync` reports an async
schema as `UnexpectedAsyncParse`).

This document records the decisions for the next stage of the package: a
structured error model, stronger primitives, declarative schemas, and a
Standard Schema adapter. [Declarative options](#declarative-options-28)
records the revision of #28 (2026-11-16), which replaced the check functions
with options; sections it superseded say so.

## Layout

| Feature directory | Owns                                                                        |
| ----------------- | --------------------------------------------------------------------------- |
| `src/core/`       | `Schema`, parsing, `is`, `SchemaIssue`, `Issues`, `SchemaNode`, annotations |
| `src/primitives/` | Leaf schemas: `string`, `number`, `boolean`, `stringbool`…                  |
| `src/composites/` | Declarative schemas: `object`, `array`, `union`…                            |
| `src/standard/`   | The Standard Schema adapter, both directions                                |
| `src/algebra/`    | `or`, `brand`, `readonly`, and the shape reshapers                          |

Every feature uses the `main`/`mini` split. Mini is the source of truth;
`main/mod.ts` is generated by `deno task gen:main` (never edited by hand).
Checks are options, the same in both: `string({ minLength: 3 })`. Main adds
methods only for the shape modifiers, the transforms and parsing:
`map(optional(string()), f)` in mini is `string().optional().map(f)` in main
(see [Declarative options](#declarative-options-28)).

## Errors

### `SchemaIssue`

Built-in schemas fail with a `SchemaIssue`, an `Enum` whose variants carry the
details a message or a UI needs:

| Variant         | Meaning                                                                    |
| --------------- | -------------------------------------------------------------------------- |
| `InvalidType`   | Wrong type: `expected` (a type name) and `received`                        |
| `InvalidValue`  | Not one of the allowed values (literals, enums)                            |
| `InvalidFormat` | A string format or pattern failed (`format`, `pattern`)                    |
| `TooSmall`      | Below a minimum: `origin` (number, string, array…), `minimum`, `inclusive` |
| `TooBig`        | Above a maximum, mirroring `TooSmall`                                      |
| `NotMultipleOf` | A `multipleOf` check failed                                                |
| `UnknownKey`    | An undeclared key in a `"strict"` object                                   |
| `InvalidUnion`  | No union branch matched; carries each branch's issues                      |
| `Custom`        | A user check failed, with a message                                        |

Every issue carries the `input` it rejected. `formatIssue(issue)` renders a
default English message; the Standard adapter uses it.

Each variant holds one details object, built by a constructor of the same name
(`InvalidType({ input, expected })`):

- `InvalidType` derives `received` from the input with `typeName`, which tells
  `null`, arrays, dates, `NaN` (`"nan"`), `±Infinity` (`"infinity"`) and
  invalid dates apart. `expected` is a free type name (`"string"`, `"object"`).
- `InvalidValue.expected` lists the allowed values; `InvalidFormat` has a
  `format` name and an optional `pattern`.
- `TooSmall`, `TooBig` and `NotMultipleOf` are discriminated by `origin`, which
  fixes the bound's type: `bigint` for `"bigint"`, `Date` for `"date"`, and a
  `number` (a value, a length or a size) for `"number"`, `"string"`, `"array"`,
  `"set"` and `"map"`.
- `UnknownKey` has the `key`, and the value under it as `input`.
- `InvalidUnion.branches` is each branch's failure as `Issues<unknown>`, in
  branch order: a branch's errors need not be `SchemaIssue`s.

### Generic `E` stays

A user-written schema may still fail with any `E`. Only built-in schemas fix
their error to `SchemaIssue`.

### `Issues<E>`: located, collected errors

Composite schemas report **every** failure, not just the first. Their error is
`Issues<E>`: a non-empty list of `{ path, error }` entries, where `path` is a
`readonly PropertyKey[]` from the composite's root and `error` is a child's
error.

`Issues` is a class (a `Struct`), so composites can recognise a child's
`Issues` at runtime and **flatten** it, prefixing the child's paths with its
key. The types follow: an `object` whose fields fail with `E1` and
`Issues<E2>` fails with `Issues<E1 | E2>`.

`Issues` are built declaratively (#28): `issues([{ path, error }, …])` takes
a non-empty list of entries with full paths (an empty list is a type error,
and `E` is the union of the entries' errors); `prefix({ issues, path })`
prepends a whole path; `concat(list)` joins a non-empty list of `Issues`.
`fromError(error)` is the one-entry root case, and `locate({ key, error })`
is the composite rule (flatten a child's error, then prefix it by `[key]`).

## Primitives

### Strict by default

A primitive accepts only its own type unless asked to coerce.

- `number()` rejects `NaN` and `±Infinity`; `number({ nan: true })` and
  `number({ infinite: true })` allow them. `-0` is accepted.
- Number checks: `int`, `safe` (safe integer), `multipleOf`, and `min`/`max`
  with inclusivity. They are options since #28:
  `number({ int: true, min: { value: 0, inclusive: false } })`.
- New leaf schemas: `bigint`, `date` (rejects `Invalid Date`), `literal`,
  `null`, `undefined`, `symbol`, `unknown`, `never`. The `null` and
  `undefined` schemas are exported as `null_` and `undefined_`: `null` is a
  reserved word, and a function named `undefined` would shadow the global.
- String checks: `minLength`/`maxLength` (named apart from the number
  bounds), `trim`, `normalize` (Unicode), `regex`, and formats `email`,
  `url`, `uuid`, `date`, `time`, `date-time`. `email` uses a pragmatic
  pattern (`EMAIL_PATTERN`), not RFC 5322; `url` is what `URL.canParse`
  accepts, plus a check that keeps it to the URL Standard on Chromium (no `%`
  left in a special scheme's host; 2026-11-18). They are options since #28: `string({ trim: true, format: "email" })`.
  #35 added `case`, `startsWith`, `endsWith` and the time formats' options
  (see [String options](#string-options-35)).
- _Superseded by #28 (2026-11-16):_ checks were first built as `self`-first
  mini functions typed on the output they refine (`int(number())`,
  `min(number(), 0, { inclusive: false })`), and `number` had a `range`
  option of `[value, "inclusive" | "non-inclusive"]` tuples. Main could not
  make them methods, so they were functions there too (`int(number()).map(…)`).

### Coercion has two named modes

`coerce: true` is **strict, lossless** coercion: convert only when the input
unambiguously means that value, and otherwise fail with `InvalidType`.

| Schema    | Accepts besides its own type                                                                                   | Rejects (examples)                              |
| --------- | -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `number`  | trimmed decimal or exponent strings (`" 12 "`, `"1e3"`); booleans → 1/0; bigints within the safe-integer range | `""`, `"0x10"`, `null`, `undefined`, `[]`, `{}` |
| `string`  | finite numbers, bigints, booleans                                                                              | `null`, `undefined`, objects, symbols           |
| `boolean` | `0`/`1`, `0n`/`1n`, and `stringbool`'s default words                                                           | `"maybe"`, `2`, `null`, objects                 |

`coerce: "native"` uses JavaScript's own `Number()`, `String()` and
`Boolean()`, with their traps (`Number("")` is `0`, `Boolean("false")` is
`true`). The result is still checked: `number({ coerce: "native" })` still
rejects the `NaN` that `Number("abc")` produces, unless `nan: true`.

### `stringbool()`

Strings from env vars, query params and forms become booleans through
`stringbool()`, not through `boolean`'s coercion of arbitrary values. It trims
and ignores case, and has configurable word lists, by default:

- truthy: `true`, `1`, `yes`, `on`, `y`, `enabled`
- falsy: `false`, `0`, `no`, `off`, `n`, `disabled`

Anything else fails with `InvalidValue`.

## Composites

Declarative schemas built from other schemas: `object`, `array`, `tuple`,
`record`, `union`, `discriminatedUnion`, `enum`, `optional`, `nullable`, and
`lazy` for recursive types.

- **Collect all:** every failing element is reported, each with its path.
- **Unknown keys are stripped** from an `object`'s output by default.
  `unknownKeys: "strict"` reports each as `UnknownKey`;
  `unknownKeys: "passthrough"` copies them (the `strict()` and
  `passthrough()` modifiers of the first design became this option in #28).
- **Async falls out of `Potential`:** a composite stays `Sync` when every child
  parse is `Sync`, and becomes `Async` otherwise.
- **Types:** `Input<S>`, `Output<S>` (alias `Infer<S>`) and `ErrorOf<S>`
  extract a schema's type parameters.

### As built (#24)

Where the implementation in `src/composites/` refines or departs from the
list above, and why:

- **`enumOf`, not `enum`:** `enum` is a reserved word. `oneOf` was rejected
  because JSON Schema's `oneOf` is a union of schemas, not of values.
- **Inputs are typed only when a child's is.** A composite's input is
  `unknown` when every child accepts `unknown`; otherwise it is the mapped
  type of the children's inputs (`ObjectInput`, `ArrayInput`, `TupleInput`,
  `RecordInput`). A `union`'s input is the _intersection_ of its options',
  since every option is tried with the same value.
- **Errors:** containers fail with `Issues<Flatten<E…> | SchemaIssue>`; a
  `union` fails with `Issues<SchemaIssue>` (one `InvalidUnion` at the root,
  holding each option's issues); `enumOf` is a leaf and fails with a bare
  `SchemaIssue`.
- _Superseded by [Optional keys](#optional-keys-28) (2026-11-16):_ optional
  fields were those whose output includes `undefined` (built with
  `optional`); a missing key was parsed as `undefined` and left out of the
  output, and a key present as `undefined` was kept.
- **`array` length checks are `minItems` / `maxItems`** (JSON Schema's
  names), apart from the string length options. They also report alongside
  element issues when the input is an array of the wrong length.
- **`tuple` has no rest element.** Extra elements fail with `TooBig`; a
  variable-length tail is an `array`. A rest form can be added as a second
  parameter later without breaking `tuple(items)`.
- **`discriminatedUnion({ key, options: { value: schema } })`** maps each
  discriminant (a string) to the schema for that case, rather than reading
  literal schemas out of each option's shape: it needs no schema
  introspection. The output carries the discriminant whether or not the
  option declares it.
- _Superseded by #28 (2026-11-16):_ `object` returned an `ObjectSchema` (a
  `Schema` whose parser remembered its shape) so `strict()`,
  `passthrough()` and `strip()` could rebuild it, and the generated main
  `ObjectSchema` extended only the _mini_ one, so
  `object({…}).strict().parseSync(x)` did not type-check. With unknown keys
  an option, `object` returns a plain `Schema` and nothing needs the shape
  at runtime.
  _Amended by #37 (2026-11-16):_ every composite now returns its `Schema`
  with a typed view of its children (`object(…).shape`, `array(…).item`,
  …), still a plain `Schema` otherwise; see
  [Typed sub-schemas](#typed-sub-schemas-37).

## Standard Schema adapter

Both directions, in `src/standard/`:

- `toStandard({ schema })` returns a Standard Schema v1 object (`~standard`
  with `version: 1`, `vendor: "sekhmet"`, `validate` and `types`), for tools
  that accept Standard Schema. It needs a schema whose input is `unknown`.
  Errors that are a `SchemaIssue` or `Issues<SchemaIssue>` become Standard
  issues through `formatIssue` and their paths; any other `E` needs a
  `toIssue` option (`toStandard({ schema, toIssue })`) that turns it into a
  message. It took `(schema, options?)` positionally until #28.
- `fromStandard(standardSchema)` wraps any Standard schema (Zod, Valibot,
  ArkType…) as a `Schema<unknown, O, Issues<StandardIssue>>`, so it composes
  with `pipe`, `map` and the composites. A `Promise` from `validate` becomes an
  `Async` parse.

Sekhmet schemas do not carry `~standard` themselves: the adapter is the only
bridge, so the core type stays free of the Standard shape.

### As implemented (2026-11-16)

The adapter targets `@standard-schema/spec` 1.1.0, whose types are copied
into `src/standard/mini/spec.ts` (no dependency). Where the spec or the
`Issues` model settled what this section left open:

- **`validate` takes an optional second argument** (`{ libraryOptions }`) since
  spec 1.1. `toStandard` accepts and ignores it: sekhmet schemas have no
  vendor options. The `StandardJSONSchemaV1` extension is not implemented.
- **`types` is type-only.** The spec marks it optional and inference-only, so
  `toStandard` declares it in the return type and sets nothing at runtime.
- **`toIssue` is per entry.** It takes `Flatten<E>`, not `E`: an
  `Issues<MyError>` becomes one Standard issue per entry, like
  `Issues<SchemaIssue>` does, instead of collapsing to one. It returns a
  message or `{ message, path? }`; the entry's path is prepended to that
  path. The requirement is enforced by overloads: without options, the error
  type must be assignable to `SchemaIssue | Issues<SchemaIssue>`.
- **An empty `issues` list** (a failure the spec's types allow but that says
  nothing) becomes one root issue with `EMPTY_FAILURE_MESSAGE`, as `Issues` is
  never empty.
- **`StandardIssue`'s entry error is the original issue**, so vendor extras
  (Zod's `code`, Valibot's `kind`) survive; its `path` is also normalised into
  the entry's `path`.
- **`toStandard` is not a `Schema` method.** It stays a function in its own
  feature, so the core type stays free of the adapter (reaffirmed in #28,
  when `Schema` gained methods from composites).

## Declarative options (#28)

Revision of 2026-11-16 (#28), diverging from Zod's all-methods style. It
supersedes the check functions of #23 and #24 and the `string().minLength(3)`
example this document first gave.

### Checks are options

Every check and transform is an option of the schema it refines, the same in
mini and main:

| Schema                   | Options                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `number`                 | `coerce`, `nan`, `infinite`, `int`, `safe`, `min`, `max`, `multipleOf`                                       |
| `string`                 | `coerce`, `trim`, `normalize`, `case`, `minLength`, `maxLength`, `startsWith`, `endsWith`, `format`, `regex` |
| `bigint`                 | `min`, `max`, `multipleOf`                                                                                   |
| `date`                   | `min`, `max`                                                                                                 |
| `boolean` / `stringbool` | `coerce` / `truthy`, `falsy`                                                                                 |
| `object`                 | `shape`, `unknownKeys` (`"strip"` by default, `"strict"`, `"passthrough"`)                                   |
| `array`                  | `item`, `minItems`, `maxItems`                                                                               |
| `record`                 | `key`, `value`                                                                                               |
| `discriminatedUnion`     | `key`, `options`                                                                                             |

`tuple`, `union`, `enumOf`, `literal` and `lazy` keep their single
positional parameter. The standalone `int`, `safe`, `multipleOf`, `min`,
`max`, `minLength`, `maxLength`, `regex`, `trim`, `normalize`, the format
functions, `minItems`, `maxItems`, `strict`, `passthrough` and `strip` are
gone; their logic is internal.

- **Bounds are `Bound<T>`:** a bare value is inclusive (`min: 0`), and
  `{ value, inclusive: false }` excludes the value itself. The common case
  stays short, the exclusive one says so in words (matching the issues'
  `inclusive` field), and one field per side can't hold two contradictory
  bounds, as separate `gt`/`gte` options could. `number`'s `range` folded
  into `min`/`max`: one way, not two. Lengths (`minLength`, `minItems`…) are
  plain inclusive counts, since an exclusive length is just the next count.
- **`format` is a `StringFormat` literal union** named as `InvalidFormat`
  reports it and as JSON Schema names it: `"email"`, `"url"`, `"uuid"`,
  `"date"`, `"time"`, `"date-time"`. Since #35 a time format can also be a
  `TimeFormat` object carrying its options.
- **`normalize` names its form** (`normalize: "NFC"`), rather than taking
  `true` for NFC as well: one spelling per form.
- **Order:** coercion first, then the transforms (`trim`, then `normalize`,
  then `case`), then the checks on the transformed value. A primitive reports
  the first failing check, in a documented order: for `number`,
  `NaN`/`±Infinity`, `int`, `safe`, `min`, `max`, `multipleOf`; for `string`,
  `minLength`, `maxLength`, `startsWith`, `endsWith`, `format`, `regex`
  (`case`, `startsWith` and `endsWith` since #35). A check of a value after a
  `map` is a `filter` (checks were once `self`-first and applied after a `map` too).
- **Allowed means accepted** (owner decision, 2026-11-16): with `nan: true`,
  `NaN` passes without any other check, since none means anything for it.
  With `infinite: true`, `±Infinity` still meets `min` and `max`, which
  compare it meaningfully (`Infinity` fails `max: 10` and passes `min: 0`),
  but skips `int`, `safe` and `multipleOf`. Finite numbers meet every check.
- **`bigint` and `date` gained bounds** (`date` compares times), as the
  issues' `"bigint"` and `"date"` origins already anticipated; neither
  coerces.
- **`object` returns a plain `Schema`**, so `object({…}).parseSync(x)` chains
  in main. _Amended by #37 (2026-11-16):_ it returns
  `Schema<…> & ObjectView<S>`, a plain `Schema` whose `.shape` is the shape
  passed; it still chains (see
  [Typed sub-schemas](#typed-sub-schemas-37)).

### Methods only for modifiers, transforms and parsing

Every main `Schema` has exactly these methods: the shape modifiers
`.array()`, `.optional()`, `.nullable()`; the transforms `.map`, `.mapErr`,
`.pipe`, `.filter`, and since #30 the
[Result-style transforms](#result-style-transforms-30) `.andThen`,
`.orElse`, `.inspect`, `.inspectErr`, `.preprocess`; and `.parse`,
`.parseSync`, `.parseAsync` (`parseSync` returns enum's main `Result`).
Since #31 it also has one getter, `.with`, whose `SchemaWith` holds the
[algebra](#algebra-31)'s methods, and since #32 one more method,
`.annotate([...])`, which adds typed annotations to a schema.

- _Amended by #37 (2026-11-16):_ the methods are unchanged, but the
  modifiers and transforms return their `Schema` with a view of the
  receiver (`.optional().inner`, `.map(f).inner`), `.annotate` returns
  `this`, `.with` returns `SchemaWith<I, O, E, this>`, and the class has a
  second static, `fromMiniView` (see
  [Typed sub-schemas](#typed-sub-schemas-37)).
- _Superseded by #32 (2026-11-16):_ the list above without `.annotate`.
  Annotating is a method because it keeps the schema (its parser and node)
  and only adds metadata, as `.optional()` keeps its value.
- _Superseded by #30 (2026-11-16):_ #28 fixed the transforms at `.map`,
  `.mapErr`, `.pipe` and `.filter`. The rule is unchanged otherwise: checks
  stay options, and only the modifiers, transforms and parsing are methods.

The modifiers belong to composites. gen-main lets a class feature _borrow_
methods from another feature's mini barrel, declared in the core feature's
config entry rather than inferred: a borrowed function takes `self` first
(`optional`, `nullable`), or names the field of its options object that the
receiver fills (`array`'s `item`). Core main imports the composites mini
barrel, which imports only core mini, so there is no import cycle, and core
main adds methods but no exports, so the kitchen-sink barrel has no new name
to collide on.

- _Amended by #31 (2026-11-16):_ a borrow can also put its methods on a
  namespace class behind a getter (`property` in its config entry), as core
  main does with the algebra mini barrel, which imports only core and
  composites mini, so there is still no cycle. Core main then exports that
  one class, `SchemaWith`, which no other entrypoint exports.

`.array()` takes no arguments: it is a shape modifier like `.optional()`,
and the length bounds stay on `array({ item, minItems, maxItems })`, one way
to write them.

### Optional keys (#28)

Owner decision (2026-11-16): an object's key-optionality is declared in its
shape, apart from value-optionality.

- **A shape value is a schema or a field entry.** A schema is a required key;
  a `Field`, `{ schema, key }` with `key: KeyPresence` (`"required"` or
  `"optional"`), says whether the key may be missing. `"required"` is the
  same as a bare schema, and the `key` field leaves room for more presences.
  `object` tells the two apart at runtime with `instanceof Schema`.
- **`.optional()` (mini `optional(self)`) is value-optional only**: it accepts
  `undefined`, and its output is `T | undefined`, everywhere (object fields,
  array items, tuple slots, the top level). It does not make a key optional.
- **The four field kinds**, under `exactOptionalPropertyTypes` (input and
  output alike, type-tested):

  | Shape value                                        | Type                          | Missing key | Present as `undefined` |
  | -------------------------------------------------- | ----------------------------- | ----------- | ---------------------- |
  | `string()`                                         | `{ a: string }`               | fails       | fails                  |
  | `string().optional()`                              | `{ a: string \| undefined }`  | fails       | kept                   |
  | `{ schema: string(), key: "optional" }`            | `{ a?: string }`              | left out    | fails                  |
  | `{ schema: string().optional(), key: "optional" }` | `{ a?: string \| undefined }` | left out    | kept                   |

- **A missing required key fails with the inner issue at `[key]`**, as before
  this decision: it is parsed as `undefined` with the field's schema
  stripped of its `.optional()` (through any `.nullable()`), so
  `string().optional()` reports `string`'s `InvalidType`. A schema that
  itself accepts `undefined` (`unknown()`, a union with `undefined_()`)
  passes, and the output keeps the key, as its type says. `object` finds
  the `.optional()` from the schema's `Optional` and `Nullable` nodes; the
  types no longer infer optionality from `undefined extends Output`.
  _Amended by #32 (2026-11-16):_ this metadata was a module-level `WeakMap`
  keyed by each modifier's parser; it is now the schema's own node.
- `discriminatedUnion` and `record` were unaffected: neither relied on the
  old inference.
- _Superseded the same day:_ an earlier decision had `.optional()` take
  `{ of: "either" | "key" | "value" }`. Carrying that through `object`'s
  types needed a fourth `Schema` type parameter or an intersection marker;
  declaring key-optionality in the shape needs neither.

### Single-object parameters

The rest of the public API follows the single-object rule. Only the receiver
is exempt: a `self`-first function whose main form is a method keeps `self`
positional, and takes at most one other parameter, so its method takes one
argument (`map(self, mapping)` is `.map(mapping)`):

- `filter(self, { error, predicate })` is `.filter({ error, predicate })`. It
  took `(self, error, filtering)` until a review of #28 caught that the
  method then took two positional arguments. `error` builds the error from
  the rejected output, `(output: O) => E`, so a check can fail with
  `Custom({ input: output, message })`.
  - _Superseded by #33 (2026-11-16):_ `error` was a constant `E`. Every issue
    carries the input it rejected, and a constant can't know it, so a filter
    couldn't build a correct `Custom` issue.
  - _Superseded by #37 (2026-11-16, owner decision):_ #33's builder returned
    the schema's own `E`, `(output: O) => E`. It now returns the filter's own
    error, `(output: O) => F`, which adds to the schema's as `andThen`'s
    does: `filter<I, O, E, P extends O, F>(self, { predicate, error }):
    Schema<I, P, E | F>` (main `.filter({ … })`). Taking `O` and `E` in one
    callback made a main `Schema` reject widening its output and error at
    once; now it is covariant in both together, which variance tests pin.
- `Issues` construction: `issues(entries)`, `prefix({ issues, path })`,
  `concat(list)` (see [`Issues<E>`](#issuese-located-collected-errors)).
- `toStandard({ schema, toIssue? })`.
- Internal helpers follow the rule too (`coerceNumber({ input, mode })`,
  `unknownKeyIssues({ input, keys })`). A type guard can't narrow a
  destructured property, so the literal guards are curried instead
  (`sameAs(value)(input)`, `oneOf(values)(input)`).
- Left receiver-first: `mapPotential(potential, mapping)`, `Potential`'s map,
  as the enum package's own `map(self, f)` is.

## Result-style transforms (#30)

Owner decision (2026-11-16): a schema chains like enum's `Result`. Each
transform is a `self`-first mini function in `src/core/mini/schema.ts` and a
one-argument main method (the receiver exception), beside `map`, `mapErr`,
`pipe` and `filter`:

| Mini                          | Callback                                    | Result                 |
| ----------------------------- | ------------------------------------------- | ---------------------- |
| `andThen(self, next)`         | `(output: O) => MaybePromise<Result<P, F>>` | `Schema<I, P, E \| F>` |
| `orElse(self, recover)`       | `(error: E) => MaybePromise<Result<O, F>>`  | `Schema<I, O, F>`      |
| `inspect(self, inspector)`    | `(output: O) => void`                       | `Schema<I, O, E>`      |
| `inspectErr(self, inspector)` | `(error: E) => void`                        | `Schema<I, O, E>`      |
| `preprocess(self, prepare)`   | `(input: J) => MaybePromise<I>`             | `Schema<J, O, E>`      |

- **`andThen`** converts or validates in code: `next` runs only on success,
  and its `Result` becomes the parse's. **`orElse`** recovers or retries:
  `recover` runs only on failure. Callbacks may return enum's main or mini
  `Result` (main extends mini). Both callbacks are typed as a `Parser`
  (`Parser<O, P, F>`, `Parser<E, O, F>`), the same function type a
  `Schema` wraps: `andThen` chains a parser function as `pipe` chains a
  schema, and the signatures name no type the package doesn't export.
- **`inspect` / `inspectErr`** tap one side for a side effect, once per
  parse, after the value is known (when an `Async` parse resolves); the
  result passes through unchanged.
- **`preprocess`** is the dual of `map`, like Zod's `z.preprocess`: it
  transforms the input before `self` parses it, and cannot fail (fail in
  `self`, or `andThen` after it).
- **Async falls out of `Potential`:** the parse stays `Sync` when the schema
  and the callback are; a promise from either makes it `Async`, and
  `parseSync` then reports `UnexpectedAsyncParse`.
- **A callback that throws panics**, as `map`'s does: the throw is not
  caught (a sync parse throws; an async one rejects). Errors are values, so a
  fallible step returns `Err` through `andThen`.
- **Laws** (tested): `andThen(s, (o) => Ok(f(o)))` equals `map(s, f)`;
  `preprocess(s, (i) => i)` equals `s`; `inspect` and `inspectErr` leave
  every result unchanged.

## Algebra (#31)

Owner decisions (2026-11-16), in `src/algebra/`. The algebra combines and
retypes whole schemas (`or`, `brand`, `readonly`), and reshapes object
shapes (`pick`, `omit`, `partial`, `required`).

| Mini                    | Main                | Result                                                         |
| ----------------------- | ------------------- | -------------------------------------------------------------- |
| `or({ left, right })`   | `.with.or(right)`   | `Schema<I & J, O \| P, Issues<SchemaIssue>>`, a `union`        |
| `brand(self, name)`     | `.with.brand(name)` | `Schema<I, Branded<O, name>, E>`                               |
| `readonly(self)`        | `.with.readonly()`  | `Schema<I, ReadonlyOutput<O>, E>`, freezing a copy             |
| `pick({ shape, keys })` | (function)          | the shape's entries for `keys`; an unknown key is a type error |
| `omit({ shape, keys })` | (function)          | the shape's other entries                                      |
| `partial(shape)`        | (function)          | every value as `{ schema, key: "optional" }`                   |
| `required(shape)`       | (function)          | every value as its bare schema                                 |

- **`or` is sugar over `union`**: `left` is tried first, `right` only when it
  fails, and when both fail the schema fails with one `InvalidUnion` at the
  root. Its input is the intersection of the sides', as `union`'s is. Chains
  flatten: an un-annotated union on either side contributes its options
  (read from its node), so `a.with.or(b).with.or(c)` and
  `union([a, b]).with.or(c)` are `union([a, b, c])`; see
  [Schemas describe themselves](#schemas-describe-themselves-32).
  _Superseded by #32 (2026-11-16):_ chains nested
  (`union([union([a, b]), c])`), pending a decision on how schemas carry
  their structure without a parser-keyed registry.
- **`brand` is type-only**: `Branded<T, B>` is `T` intersected with a
  property keyed by the exported `unique symbol` `BRAND`, so a plain `T` is
  not assignable to it, brands compose (`Branded<Branded<T, "A">, "B">` is
  both), and parsing is the brand's smart constructor. At runtime `brand`
  returns its schema as is and records nothing. The name is a value, not a
  type argument, because `brand<"UserId">()` can't infer the schema's other
  type parameters.
- **`readonly` freezes a copy**, never the value the schema produced, which
  may be the caller's input (`unknown()` passes it through): an array becomes
  a frozen `slice()`, and a plain object (prototype `Object.prototype` or
  `null`) a frozen copy with the same prototype and own property
  descriptors. Freezing is shallow. Anything else passes through unchanged:
  primitives can't change, `Object.freeze` doesn't reach the internal state
  of a `Map`, `Set` or `Date` (a frozen `Map` still `set`s), and a class
  instance can't be copied without bypassing its constructor.
  `ReadonlyOutput<O>` distributes over unions: `Map` → `ReadonlyMap`, `Set`
  → `ReadonlySet`, arrays, tuples and objects → `Readonly`, the rest
  (primitives, functions) unchanged.
- **Reshapers work on shapes, not schemas.** `object` returns a plain
  `Schema` that doesn't carry its shape (#28), so a reshaper takes the shape
  value and returns another, which `object` then builds: `object({ shape:
  partial(user) })`. Carrying the shape on the schema would need an
  `ObjectSchema` subclass or a fourth type parameter, which #28 removed.
  (Since #32 an object's node holds its shape at runtime, typed as any
  `Shape`; the reshapers still take the typed shape value.)
  _Amended by #37 (2026-11-16):_ an object now carries its typed shape as
  its view, so `partial(user.shape)` reshapes an existing object; the
  reshapers still take and return shapes.
  `partial` changes only key-optionality and `required` only drops it: a
  value-optional schema (`.optional()`) still accepts `undefined`, so the
  four field kinds of [Optional keys](#optional-keys-28) map onto each other
  as their table says. `pick` and `omit` take `K` as a `const` type
  parameter, so the keys still infer when the call is `object`'s `shape`.
- **No `extend`:** a shape is a plain object, so `{ ...shape, extra }`
  extends it. Declare a standalone shape `satisfies Shape`, not `: Shape`,
  so its keys and each `key: "optional"` stay literal.
- **`.with` namespace:** the main `Schema` has a `with` getter returning a
  `SchemaWith`, a class generated in core main beside `Schema`, whose methods
  are `or`, `brand` and `readonly`; each returns a main `Schema`, so
  `string().with.or(number()).map(String)` chains. The algebra sits behind a
  namespace so the main `Schema`'s own methods stay the modifiers,
  transforms and parsing. `SchemaWith` holds the _mini_ `Schema` its getter
  was called on: holding the main class, whose getter returns `SchemaWith`,
  makes TypeScript's variance measurement circular and order-dependent (a
  `SchemaWith<unknown, string>` type-checked as a `SchemaWith<unknown, "a">`).
  _Amended by #37 (2026-11-16):_ it holds `Self extends mini.Schema<I, O,
  E>`, which the getter fills with `this`, so `.with.readonly()` and
  `.with.brand()` keep the receiver's view; the bound stays the mini class.
- **Dropped: `and`** (intersection) and its `InvalidIntersection` issue.
  Every use is covered unambiguously by shape spread, options, `filter` or
  `andThen`, and merging two different outputs has no good general rule.

## Schemas describe themselves (#32)

Owner decisions (2026-11-16), in `src/core/mini/node.ts` and
`src/core/mini/annotation.ts`. A schema carries what it is and what it
means as data, in its own params, so tools (a form generator, later
`toJsonSchema`) read it without parsing, and nothing is kept in
module-level state.

- **Params.** `Schema<I, O, E>` is a `Struct` of
  `SchemaParams { parse, node, annotations }`, built with
  `new Schema({ parse, node?, annotations? })`: `node` defaults to
  `Opaque()` and `annotations` to `[]`. Under `exactOptionalPropertyTypes`
  an omitted field is left out, never `undefined`. Every field is
  immutable, so a main view (`Schema.fromMini`), whose constructor copies
  the params, can't be told from sharing them.
- **`SchemaNode`** is a public `Enum`: `Opaque`, `Leaf`, `Optional`,
  `Nullable`, `Object`, `Array`, `Tuple`, `Record`, `Union`,
  `DiscriminatedUnion`, `Lazy`, `Transform`, `Pipe`, `Readonly`, `Custom`.
  Read it with `nodeOf(schema)`, and walk it with `children(node)`.
  - A `Leaf` is told apart by `type` and keeps its options **as passed**
    (`string({ minLength: 1 })` is `{ type: "string", options:
    { minLength: 1 } }`, `string()` has `options: {}`); `literal`,
    `enumOf` and the option-less primitives carry their value(s) or nothing.
  - Composites keep their options and children as passed; an absent
    option is a present `undefined` field (`array({ item })` has
    `minItems: undefined`), so every node of a variant has the same keys.
  - A transform (`map`, `mapErr`, `andThen`, `orElse`, `filter`,
    `inspect`, `inspectErr`, `preprocess`) records
    `Transform { step, inner }`, naming its step: **no node holds a
    callback**, since a function can't be read. `Lazy { getter }` is the
    exception, since a recursive schema reaches itself only through it;
    `children` doesn't call it, so a walk always ends. `pipe` records
    `Pipe { inner, next }`.
  - `readonly` records `Readonly { inner }`; `brand` is type-only and
    returns its schema, so it records nothing.
- **Custom kinds.** A schema built outside the package describes itself
  with a `Custom { kind, data, children }` node: `nodeKind<D>({ name })`
  defines a kind (a value you hold; kinds are told apart by identity),
  `custom({ kind, data, children? })` builds the node, and
  `customData({ node, kind })` reads `Option<D>`, `None` for another kind
  or variant. The kind's `D` is erased when the node is built; identity is
  the proof, restored by one isolated, commented cast.
- **`WRAPPED` is gone.** `object` still parses a missing required key with
  the field's schema stripped of `.optional()` (through `.nullable()`), but
  `withoutOptional` reads the `Optional` and `Nullable` nodes instead of a
  parser-keyed `WeakMap`. It sees through nothing else (not `Readonly`, a
  transform or `lazy`). `withoutOptional` and `acceptNull` are typed as
  overloads over an erased implementation, as the composites are: a node
  holds its inner schema as `AnySchema`, and the object runs it as a child.
- **`or` flattens through the node.** A side whose node is a `Union` with
  no annotations contributes its options, one level as written, so
  `union([a, b]).with.or(c)` and `a.with.or(b).with.or(c)` are both
  `union([a, b, c])`, failing with one `InvalidUnion` of three branches. A
  union with annotations stays one branch, so its annotations still
  describe it. This resolves the algebra's pending flattening (#31).
- **Annotations.** `annotationKey<T>({ name })` defines a typed key (a
  value you hold, told apart by identity). A key is callable: `label("Name")`
  makes an `Annotation`, and `label(1)` is a type error.
  `annotate(self, annotations)` (main `.annotate([...])`) returns the same
  parser and node with the annotations appended; a later entry for a key
  wins. Every other operation starts with none: annotations describe the
  schema they are on, and a `map`'s output is another value. The exception
  is `brand`, which is type-only and returns its schema as is, so the
  annotations survive. `Schema.fromMini` is not an operation but a view of
  the same schema, built from its params, so it keeps them too.
  `annotation({ schema, key })` reads `Option<T>`, falling back through
  `Optional`, `Nullable` and `Readonly` only, so a field's `.optional()`
  keeps its label. `description` and `title` are the well-known keys, as
  JSON Schema's.
- **Why no fourth type parameter.** Metadata in the type
  (`Schema<I, O, E, M>`) would thread through every signature, every
  `Input`/`Output`/`ErrorOf`, and every composite's inference, for values
  only tools read. A typed key gives the same type safety at the read site
  (`annotation({ key: label })` is `Option<string>`) with the three
  parameters unchanged.
- **Why no registries.** A `WeakMap` keyed by a parser (or schema) is
  module-level state: it can't be serialised, it's invisible in a schema's
  value, and a copy of the schema loses it. The owner's rule is no
  module-level state; `deno task ci`'s `module-state` readiness check
  enforces it on `packages/schema/src`.
- **Doc lint.** `SchemaNode` (an `Enum`) and the `Option` that `customData`
  and `annotation` return are cross-package types the package doesn't
  re-export; they are allowlisted under #11 with the existing ones. The
  avoidable refs were designed away: `SchemaNodeVariants` is written out
  rather than `Split`, `NodeKind` is a plain object, and `Annotation` and
  `CustomNodeDetails` are classes of their own, not `Struct`s.
- **Typed keys can't be forged (fixed after review, 2026-11-16).**
  `AnnotationKey<in out T>` and `NodeKind<in out D>` are invariant, so a key
  or kind can't be read back at a narrower or wider type than it was
  written. `Annotation` and a `Custom` node's `CustomNodeDetails` have
  private constructors and `#private` fields, so no object literal passes
  for one (the `SchemaNode` constructor can't be handed a forged `Custom`);
  each is built only by a static `of` typed by its key or kind, which
  calling a key and `custom()` use. The two casts, one per lookup, stay the
  only ones.
- **Later (not in this change):** `toJsonSchema` and Standard JSON Schema,
  reading nodes and annotations.

## Type guards (#34)

Decisions (2026-11-16), in `src/core/mini/guard.ts`.

- **`is(schema)` is a curried function**, `(input: I) => input is O & I`,
  like the package's other guards (`literal`'s `sameAs(value)(input)`): the
  guard is a value, so it passes straight to `Array.prototype.filter`, an
  `if`, or `filter({ predicate })`. It is not a main method: `schema.is` would
  have to be bound before `values.filter(schema.is)` worked, and a method
  taking the input (`schema.is(input)`) can't be passed at all. Its parameter
  is `schema`, not `self`, so `gen:main` re-exports the function from
  `@sekhmet/schema/core` rather than making it a method; it accepts a main
  `Schema`, which extends mini's.
- **`O & I`, not `O`:** a type predicate must be assignable to its parameter,
  and the intersection keeps what the caller already knew about the input.
  For an `unknown` input it is just `O`.
- **Sound only for schemas that don't transform** (output ⊆ input), which
  TypeScript can't express, so the TSDoc says so. The guard reports that the
  schema accepted the input, then claims the input is the output:
  `string({ trim: true, maxLength: 1 })` accepts `" a "` (three characters),
  and `number({ coerce: true })` narrows the string `"42"` to `number`. Use
  `parseSync` and keep the output when a schema transforms.
- **An async schema panics.** The guard parses with `parseSync`; a schema
  that parses asynchronously can't answer a synchronous guard, so it is a
  programmer error and the guard throws a `TypeError` (the package's panics
  are plain `TypeError`/`RangeError` throws) rather than returning `false`,
  which would silently reject every value.

## String options (#35)

Implemented 2026-11-16, in
`src/primitives/mini/string.ts`, `string-checks.ts` and `string-formats.ts`.
Every new option is kept in the `Leaf` node as passed, like the rest (#32).

- **`startsWith` and `endsWith`** take a literal prefix or suffix and fail
  with `InvalidFormat`, of format `"starts-with"` or `"ends-with"`: kebab
  case, as JSON Schema names its formats (`"date-time"`). They compare UTF-16
  code units, case-sensitively, on the transformed string, and run after the
  lengths and before `format` and `regex`, the cheap literal checks first.
  The issue carries no `pattern`, since an affix is not a pattern; the
  expected affix is in the schema's node.
- **`case: "lower" | "upper"`** is a transform, like `trim` and `normalize`:
  it never fails, and runs after them, so the order is coerce → trim →
  normalize → case → checks. Normalizing first means a compatibility form
  (`NFKC` turns `"ﬁ"` into `"fi"`) is cased too. The conversion is
  `toLowerCase`/`toUpperCase`, Unicode's default mapping rather than the
  runtime locale's, so a schema parses the same everywhere. It can change the
  length (`"ß"` uppers to `"SS"`), which is why the length checks come after
  it. A string literal union (`LetterCase`) rather than two booleans, so
  `lower` and `upper` can't both be set.
- **Time format options attach to the format.** `"time"` and `"date-time"`
  take options as a `TimeFormat` in the `format` option itself:
  `format: { name: "date-time", precision: 3, offset: "allowed" }`.
  - `precision` (`FractionalDigits`, `0` to `9`) is the exact number of
    fractional-second digits, and setting it makes the seconds required
    (`0` is whole seconds). Left out, the seconds and any number of digits
    are optional. The bound is `9`, nanoseconds, as `Temporal` keeps them; a
    literal union makes `precision: 10` a type error, not a runtime one.
  - `offset` (`OffsetRule`) is `"required"`, `"allowed"` or `"forbidden"`.
    A local time is `offset: "forbidden"`; there is no separate `local`
    flag, which could contradict the offset rule. Left out, it is
    `"forbidden"` for `"time"` (an ISO partial time) and `"required"` for
    `"date-time"` (RFC 3339), the bare names' behavior before #35.
  - **Why in `format`, not a sibling `time` option:** a sibling could be set
    with `format: "email"` or with no format, a combination that means
    nothing; nested in the format, options exist only where they apply. The
    bare name stays the short form of the object with every option left out
    (`"time"` is `{ name: "time" }`), as a bare `Bound` value is the
    inclusive `{ value, inclusive: true }`. The `Leaf` keeps whichever was
    passed.
  - **Grammar** (unchanged by the options): 24-hour `HH:MM`, seconds `00` to
    `59` (no leap second: `23:59:60` fails), a `.` decimal mark only, an
    offset of `Z` or `±HH:MM` with hours `00` to `23` (`-00:00` passes), and
    an upper-case `T` and `Z`. A date-time's date must exist in the
    calendar. The patterns are composed from regex literal fragments' `source`
    (`/\d/.source`), so no escape is ever written twice; the archived
    prototype wrote `\\d` inside regex literals, which matches a backslash
    and a `d`, not a digit.
  - The issue stays `InvalidFormat` naming `"time"` or `"date-time"`, with
    no `pattern` (a date-time's calendar check isn't one); the options are
    in the node.

## Typed sub-schemas (#37)

Owner decisions (2026-11-16), in `src/core/mini/view.ts` and every
composite, wrapper and transform. A schema built from other schemas exposes
them, typed exactly as passed, so a caller can reach a field's schema
(`user.shape.name`) without walking the untyped node.

- **Views are own properties.** Every adapter-like constructor returns
  `Schema<I, O, E> & XView<…>`: `viewed({ init, view })` is
  `Object.assign(new Schema(init), view)`, so a view's properties are the
  same child references the node holds, and add no state. Each view type
  is exported, and names follow the node:

  | Built by                                                                              | View                           | Properties                                                |
  | ------------------------------------------------------------------------------------- | ------------------------------ | --------------------------------------------------------- |
  | `object`                                                                              | `ObjectView<S>`                | `shape` (field entries stay entries: `.shape.age.schema`) |
  | `array`, `.array()`                                                                   | `ArrayView<S>`                 | `item`                                                    |
  | `tuple`                                                                               | `TupleView<T>`                 | `items`                                                   |
  | `record`                                                                              | `RecordView<K, V>`             | `key`, `value`                                            |
  | `union`                                                                               | `UnionView<T>`                 | `options`                                                 |
  | `discriminatedUnion`                                                                  | `DiscriminatedUnionView<K, M>` | `key`, `options`                                          |
  | `optional`, `nullable`, `readonly`                                                    | `WrapperView<S>`               | `inner`                                                   |
  | `lazy`                                                                                | `LazyView<S>`                  | `getter` (returns `S`)                                    |
  | `map`, `mapErr`, `filter`, `andThen`, `orElse`, `inspect`, `inspectErr`, `preprocess` | `TransformView<S>`             | `inner`                                                   |
  | `pipe`                                                                                | `PipeView<S, N>`               | `inner`, `next`                                           |

- **Children are captured exactly.** A child parameter is typed
  `S & Schema<I, O, E>` with `S extends Schema<I, O, E>`: TypeScript infers
  `I`, `O`, `E` as before and `S` as the child's whole type, view included.
  So views nest (`user.optional().inner.shape.name`), and a child stays
  main or mini as it was built. `record` takes its key and value schemas
  as two more type parameters (seven in all); every output type is
  unchanged. (A generic `S extends AnySchema` with `Input<S>` in the return
  fails in main's methods, where `S` is `this`: the conditional defers.)
- **Transforms are precise.** `string().map(f).inner` is the receiver, with
  its own view (`TransformView<this>` in main), so hovers grow with a
  chain's length; a 33-step `.map().optional()` chain is type-tested to stay
  fast and within depth limits. A transform's own view is `inner`, so the
  receiver's view (`.shape`) is not on the result's type, correctly.
- **`annotate` keeps the view.** It builds a new `Schema` over the same
  parser and node with the annotations added, and copies the receiver's
  view (its own enumerable string-keyed properties) onto it: `annotate(self,
  …)` is `Schema<I, O, E> & ViewOf<S>`, and main's `.annotate()` is
  `Schema<I, O, E> & ViewOf<this>`.
  _Revised after review (2026-11-16):_ it first returned `S` (`this`), a copy
  with the receiver's prototype; that copy was not an `S` (a subclass lost
  its `#private` state) and copying a frozen schema threw.
  _Owner decision (2026-11-16):_ `ViewOf<S>` would still promise a
  subclass's prototype members (getters, methods, overrides), which the
  copy lacks, so `annotate` panics with a `TypeError` on a receiver whose
  prototype chain has members beyond mini's and main's `Schema.prototype`.
  A subclass adding only own fields is annotated: its fields are its view.
- **Algebra.** `readonly` views its `inner`. `brand` returns its schema
  itself, so it keeps the schema's view (`& ViewOf<S>`); main's `brand` and
  `.with.brand` return a receiver that is already main as is (a user
  subclass included) and convert only a mini one (gen-main's `identities`
  and `identity`). `or` gets no view: flattening makes its option count
  unknown from its type, so it returns a schema over the union's params
  with no own properties, in mini as in main.
  _Revised after review (2026-11-16):_ main's `brand` went through
  `fromMiniView`, which panics on a subclass; and mini `or` returned the
  union itself, whose own `options` its type didn't promise.
- **`.with` keeps views.** `SchemaWith<I, O, E, Self>` holds the receiver
  as a type parameter bounded by the _mini_ `Schema` (`Self extends
  mini.Schema<I, O, E> = mini.Schema<I, O, E>`), and the getter returns
  `SchemaWith<I, O, E, this>`: `.with.readonly().inner` is the receiver and
  `.with.brand(…)` keeps its view. Bounding by the mini class keeps #31's
  fix: the #31 covariance tests stay green, as do new ones checking
  narrowing first (the #31 bug was order-dependent) for outputs, views and
  `Self`.
- **Reserved keys.** `viewed` rejects, at the type level, a view key that
  would collide: `schema` (it marks an object's field entry), every symbol
  (a schema keeps its params under `struct`), and the main `Schema`'s
  members (`MainSchemaMember`, type-tested to match main exactly).
  _Revised after review (2026-11-16):_ a view widened by assignment slips
  past the types, and `Object.assign` copied a smuggled `struct` (replacing
  the parser) or `map`. `viewed` now also panics with a `TypeError` on a
  symbol key, a reserved name (`RESERVED_VIEW_NAMES`, a frozen record whose
  type names each one) or `__proto__`.
  `ViewOf<S>` reads the view off a schema by omitting them. Two hazards
  were fixed with it: `WithOptionalKeys` now requires `schema` in the
  optional-field pattern (a `discriminatedUnion({ key: "optional", … })`
  was read as an optional field), and the node's `fieldSchema` checks
  `instanceof Schema` first, as `object` does.
- **Power users.** `viewed({ init, view })` with a `custom()` node gives a
  composite of your own typed children.
- **gen-main.** A class feature can carry views (`views: { any:
  "AnySchema" }`): its main class gets `fromMiniView`, which builds a main
  instance over the same params and copies the value's own properties,
  always (a main receiver's view comes along), and panics with a
  `TypeError` on any other prototype than mini's or main's `Schema` (a
  subclass would lose its behaviour in the copy). A returned intersection
  naming one wrap target converts through it; `self: S & Schema<A, B, C>`
  and `self: S extends AnySchema` render `S` as `this` (as `Self` on a
  namespace class), and so does a field method's options type parameter
  constrained to `Schema<A, B, C>` (`array`'s `item`).

## Parsing to a Vow of an Outcome (#84)

Status: **Implemented** (2026-11-20). Supersedes `Potential` wherever the
sections above mention it (`Sync`/`Async`, `mapPotential`, `parseAsync`);
those sections are kept as history.

- **`parse(schema, { input, panics })` returns
  `Vow<Outcome<O, E, unknown>>`.** Sekhmet's rule is that anything that may
  be sync or async returns a `Vow` (`@sekhmet/vow`), which resolves inside
  the call when the work was synchronous; a caller that wants a `Promise`
  calls `wait`. `Potential` duplicated `Vow`, stayed `Async` after its
  promise settled, and gave every combinator two code paths. It is deleted,
  with `Sync`, `Async`, `from`, `mapPotential`, `PotentialVariants` and the
  `./core/mini/potential` export (pre-1.0: no shims).
- **Schema takes a panic runtime, like lifetime.** `Err(E)` is the expected
  failure; a throw or a rejection in user code (a parser, refinement,
  transform, `preprocess`, a `lazy` getter, a foreign Standard `validate`)
  is a panic, caught by `panics` (`catchUnwind`/`catchUnwindAsync`),
  reported to its hook, and settled as `Panicked`. `Outcome` (#86) keeps the
  two channels apart, so `mapErr` and `orElse` never see a panic. Rejected:
  binding a runtime only on async steps (a rejection would be reported while
  the vow never settled), and `Result<O, E | Panic>` (it mixes bugs with
  expected failures).
- **`panics` is a `PanicBoundary`**, `Pick<PanicRuntime, "catchUnwind" |
  "catchUnwindAsync">`, the same slice `@sekhmet/lifetime` takes. The
  options object follows the named-arguments rule, with the schema as the
  receiver, so main's method is `schema.parse({ input, panics })`. It
  returns a `Vow` of panic's main `Outcome` class, with its methods:
  gen-main converts a carrier's value (`Vow` is one, mapped with vow's
  `map`) as it converts a `Promise`'s.
- **A schema holds a runner.** `SchemaParams.run` is a `Runner<I, O, E>`:
  `(options: ParseOptions<I>) => Vow<Outcome<O, E, unknown>>`.
  `new Schema({ parse })` still takes a user `Parser` (a `Result` or a
  promise of one) and guards it; composites build theirs with
  `new Schema({ run })` from their children's `parse`. Every callback handed
  to a vow continuation runs under the boundary (through `parse`, `guard`,
  or the internal `step`), internal code included, since it can throw when
  it reads a user value (a getter, a Proxy trap): none can throw inside a
  `resolve`, where the parse would never settle. The one exception is by
  design: a panic hook that throws while reporting (a `HookFailurePanic`)
  escapes every boundary, per the panic runtime's contract (lifetime does
  the same), so an async parse may then never settle, and the failure
  surfaces as an unhandled rejection.
- **Composites join children with `all`**, added to `@sekhmet/vow`: the
  n-ary `zip`, which stays synchronous when every child was. A child's panic
  panics the composite (the first by key order); a union does not try the
  next option after a panic.
- **`parseAsync` is dropped** in favour of `wait(parse(…))`.
- **`parseSync(schema, input)` keeps its shape and takes no runtime.**
  While it runs, its boundary catches nothing, so a throw unwinds to its
  caller. An async schema is still `UnexpectedAsyncParse`. Once
  `parseSync` has returned, the boundary catches: a panic the abandoned
  parse raises later settles it as `Panicked`, which nothing reads and no
  hook reports. _Revised after review (2026-11-20):_ the first version's
  boundary never caught, so such a panic escaped as an unhandled rejection.
- **`toStandard({ schema, panics })`** takes a runtime. `validate` returns
  the Standard result when the vow is already resolved and `wait(…)`
  otherwise; a panic is reported, then resumed with `resumeUnwind`, so it
  throws (or rejects) out of `validate` to the foreign caller.
  `fromStandard` passes a foreign promise through the parse's boundary, so a
  rejection is `Panicked`.
